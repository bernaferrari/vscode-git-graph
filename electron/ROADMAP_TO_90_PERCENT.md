# Git Graph → 90% Competitor Readiness Plan

## Current readiness snapshot (v3)

- **Product focus has moved away from blanket competitor parity.**
    - Guided mode centers on graph navigation, branch selection, commit/stage/sync, previewed integration, and undo history.
    - Control mode keeps advanced surfaces such as worktrees, pull requests, workflows, collaboration, diagnostics, and repo policy behind the compact Tools menu.
    - Misleading parity claims are intentionally removed from the release criteria.
    - Pull workflows include explicit fast-forward-only execution paths in the primary UI.
    - Commit signing includes richer SSH key management (discovery, selection, and allowed signers file config).

## Success criteria for “90%”

- The core daily workflow is fast, understandable, and undo-aware.
- Advanced/professional workflows are available in Control mode without taking over the Guided first-run surface.
- Previewed integration is a differentiator: merge, rebase, and squash show real conflict/risk data and predicted graph shape before execution.

## Where we are relative to competitors right now

- **GitKraken**: comparable on core graph/stage/sync/history operations; broader collaboration and automation surfaces are intentionally secondary.
- **Tower**: comparable on conflict and review-oriented workflows; Guided mode favors fewer paths over full surface density.
- **Sublime Merge**: comparable on key graph, staging, search, and diff workflows.

Git Graph should now optimize for confidence in history-changing operations rather than continuing to expand parity checklists.
